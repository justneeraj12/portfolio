SYS.01

ROBOTICS · PERCEPTION · CONTROL

Vision-only leader-follower warehouse convoy

ROS 2 JAZZY · GAZEBO HARMONIC · PYTHON · YOLOv8n · OPENCV · EKF · DOCKER

I built a multi robot convoy in ROS 2 and Gazebo using camera geometry, wheel odometry, and TRACK / PREDICT / SAFE STOP states. I fixed RGB/BGR channel and stale timestamp bugs, then reached 100% valid detections with 0.0323 m range RMSE and 0.1569° bearing error.

30 disturbance runs / 0 hits 23.09 ms cam to meas p95 61 passing CI tests
Deep architecture note

The main bugs were an RGB/BGR channel mismatch and stale frame timestamps. The supervisor keeps fresh vision tracking, short odometry prediction, and the timed zero velocity stop as separate states.

SYS.02

LINUX · SECURITY · LOCAL INFERENCE

CPU first local face authentication for Linux

C++17 · C · PAM · QT 6 · OPENCV DNN · V4L2 · UNIX SOCKETS · LIBSODIUM

This is a local Linux face unlock project. A small PAM client talks to a C++17 daemon over a checked UNIX socket. Camera capture uses V4L2, profiles are encrypted with libsodium, and the model pipeline runs on CPU without CUDA.

6.6 ms detection / CPU 12.6 ms embedding p95 ONNX zero CUDA
Deep architecture note

The PAM client only sends a small request to the user level daemon. The socket checks the connecting process, camera and model work stay outside PAM, and libsodium protects the saved face profiles.

SYS.03

WAYLAND · NATIVE UI · RECOVERY

Nocturne Operations Console for Hyprland

C++ · QT 6 · QT QUICK · LAYERSHELLQT · WAYLAND · DBUS · LINUX IPC

Nocturne is the desktop I wanted for Hyprland. It is built in C++ and Qt 6 and uses regular Linux services instead of a pile of polling widgets. Install and update steps take a snapshot first, keep diagnostics read only, and ask before rollback.

WAYLAND LayerShellQt SNAPSHOT rollback CI Ubuntu + Arch
Deep architecture note

The Qt 6 shell listens to Linux services through DBus and native IPC. Before an upgrade it records the working state. Repairs and rollback always ask first, then check the system again when they finish.

SYS.04

AUDIO · CLASSICAL ML · RESEARCH

Cross-lingual speech emotion recognition

PYTHON · AUDIO SIGNAL PROCESSING · ACOUSTIC FEATURES · ML EVALUATION

This is a class research project on whether simple acoustic features carry across languages. The data split keeps speakers separated, and Polish nEMO stays out of training for the final cross language test.

13 corpus splits 8 languages nEMO held out target
Deep architecture note

The feature set covers MFCCs, pitch, energy, spectral shape, and voice quality. The speaker splits are saved before training. Preprocessing only learns from training data, and the Polish test set is used once at the end.
